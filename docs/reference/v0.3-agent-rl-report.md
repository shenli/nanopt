# v0.3 Mini Agent RL reference report

## Decision

The v0.3 Mini Agent RL gate passed on candidate `85ca98b`. A clean locked environment ran on the
validated NVIDIA RTX 4070 Ti SUPER host. The model and LoRA adapters ran on CUDA; every tool call,
public test, and hidden verification ran in the pinned network-disabled Docker sandbox. The
existing Whisper service remained active throughout the run.

## Exact rollout and update contract

The run collected four groups of four independently reset episodes. Every group shared one task
and immutable snapshot hash. Across 16 episodes it retained 80 action turns and 3,649 active
sampled tokens. Each action stored the exact online prompt IDs, sampled IDs, action mask, FP32
behavior log probabilities, frozen Agent SFT reference log probabilities, parse status, tool, and
group-relative episode advantage.

All four groups were non-degenerate. Hidden reward was revealed only after termination and never
entered an observation. The trainer accepted only policy-lag-zero groups, consumed stored token
IDs directly, and completed 20 optimizer steps with one clipped update epoch per fresh group.

| Training metric | Result |
| --- | ---: |
| Groups / episodes / action turns | 4 / 16 / 80 |
| Mean sampled outcome reward | 0.6719 |
| Sampled action validity | 91.25% |
| Non-degenerate groups | 4/4 |
| Optimizer steps | 20 |
| Peak reserved VRAM | 14.094 GiB |

## Policy-boundary selection

Sparse outcome updates were not monotonic. Greedy validation reward by policy version was:

```text
Agent SFT parent v0: 1.000
Agent RL v1:         1.000  ← selected
Agent RL v2:         0.233
Agent RL v3:         1.000
Agent RL v4:         0.000
```

The frozen rule selects the highest-reward post-update boundary and breaks ties toward the
earliest version; the untrained parent is not eligible. Version 1 was therefore published. This is
not hidden evidence smoothing: all later rewards, rollout groups, metrics, and the terminal-policy
staleness study remain in the run artifacts. The rejected terminal-only publication attempt is an
educational example of why a final optimizer step is not automatically the best checkpoint.

## Fresh versus stale trajectories

The terminal training policy rescored the newest and oldest retained exact action IDs. Neither set
was reused for an update.

| Retained data | Policy lag | Mean absolute log-ratio | Maximum absolute log-ratio | Approx. ESS fraction |
| --- | ---: | ---: | ---: | ---: |
| Fresh | 1 | 0.001608 | 0.2271 | 0.9999 |
| Stale | 4 | 0.028175 | 3.4123 | 0.9813 |

The stale mean drift was about 17.5 times the fresh drift. This does not define a universal stale-
data cutoff; it demonstrates why v0.3 measures old groups but trains only on fresh ones.

## Credit assignment and tool budget

All-action credit covered 3,649 sampled tokens. A terminal-action-only counterfactual would cover
340 tokens, or 9.32%. The reference objective assigns each episode advantage to every sampled
action token; the ablation is a coverage study, not a separately trained policy.

On the one task-level validation task, both the parent and selected Agent RL adapter received
partial reward 0.333 with a two-tool cap and reward 1.0 with a five-tool cap. This makes the budget
effect visible without misreporting partial hidden-test credit as zero.

## Interpretation

The gate establishes an exact-token, stateful, short-horizon policy-optimization slice with hidden
outcomes, strict fresh-data enforcement, policy-age evidence, credit coverage, budget evaluation,
and safe policy-boundary selection. It does not establish broad coding skill, long-horizon credit
assignment, scalable rollout throughput, or safe unrestricted host access. The suite contains five
tiny educational tasks and one validation task.
